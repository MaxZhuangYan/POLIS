# Polis 演示手册（商业路演，5–7 分钟）

目标：演示者打开一个**已经走到第 10 天白天**的存档，手上还有一件没处理的事（岔路或默契）、一张没读的明信片，
不用等模拟，沿一条固定路线讲完三个卖点。

三个卖点，以及每个画面证明了什么：

| 卖点 | 证明它的画面 | 为什么算数 |
|---|---|---|
| **AI 有自己的立场**：玩家不能操控它，它会说「不」 | 岔路 → 它的回应（拒绝 / 调整）→ 强制执行及其代价 | 它引用的是玩家以前说过的原则；「依据」一栏列的是数据库里的事实；强制执行要花 30 Scrip、扣信任，还会在它心里留下一条「被迫」的烙印，下次它会拿这条烙印说话 |
| **记忆由玩家塑造**：玩家的每个选择都变成它的原则 | 烙印抽屉（5 格槽位）→ 记忆 tab（谁的主意） | 每条烙印写着诞生场景、被引用次数；记忆按「你的话 / 它认同 / 它没认同 / 被迫 / 它做了 / 后来 / 别人」打标签，一眼分得清哪些是你的主意、哪些是它自己的、哪些是别人传的 |
| **一个故事全是真的的社会**：居民会借钱、违约、记仇、传话 | 关系 tab（带出处的传闻）→ 公告栏 → 账本 → 明信片 → 档案卷 | 每个人名、数字、事件都对应数据库里真实的一行；传闻写明「听 X 说」；明信片不写收益率，数字只在账本里；`node scripts/causal-chains.mjs <db>` 能把一条因果链逐行翻到表 `#id` |

## 先说清楚（现场不要说过头）

- **没有模型。** 存档由离线规则引擎生成，右上角标着「离线模式 · 规则引擎」。所有台词、烙印、明信片是模板 + 数据库的行拼出来的
  （明信片底部写着「由规则整理」，烙印来源标「规则凝练」）。**不要说「这是大模型写的」。** 如果配置了模型端点
  （`POLIS_LLM_URL` 等，见 `doc/PLAY.md`），之后新产生的判定 / 明信片可能经模型润色，且都有校验门和规则兜底；
  这条路径**没有**在这个存档的路线里验证过，不要当作卖点承诺。
- **前 9 天是「测试快进」压出来的。** 屏幕上方有「已测试快进 2xx 小时（正式玩法为现实时间 1:1）」。规则一条没缩短，
  只是时钟被往前拨了；被问到就如实说。
- **世界有随机。** 每次生成的存档，居民、借款、传闻都不同；以脚本打印的清单为准，不要背稿里的具体名字。

## 准备（演示前，约 2 分钟 + 第一次编译）

```bash
# 1. 生成存档：只通过游戏自己的 HTTP API 和「测试快进」，大胆型守护灵玩前 9 天，
#    再逐小时往后找一个「白天、有待办、有未读明信片」的时刻停下。世界不给就自动重来（最多 4 次）。
npm run scenario -- pitch --db ./polis-pitch-master.db --force

# 2. 屏幕上打印的三段就是你的小抄，复制到一个不进仓库的地方：
#    PENDING（现在有什么待办、还剩几小时）
#    IF THE PRESENTER ANSWERS ...（剩余时间最长的那个岔路，每个选项它会照做还是拒绝——在存档的副本上用真实接口试出来的）
#    WHAT TO SHOW（拒绝的原话、被迫的烙印、居民难处、传闻、借款、因果链，每条带表 #id）
```

每次彩排或正式开场前，**从这份原件复制一份来用，再把时钟校准回存档建成的那一刻**：

```bash
# 先停掉正在跑的 dev server
cp ./polis-pitch-master.db ./polis-test.db
cp ./polis-pitch-master.db.pitch.json ./polis-test.db.pitch.json
npm run scenario -- pitch --rewind     # 只改时钟偏移；不碰任何剧情行
npm run dev:test                       # 打开 http://localhost:3000
```

为什么要这一步：模拟时钟 = 现实时间 + 存档里保存的偏移，所以存档放一小时，游戏里就过一小时：岔路 24 小时不答由它自决，
白天会变成夜里。`--rewind` 把时钟拨回建档那一刻；**之后时钟照常走**，所以从校准到开讲不要超过半小时。
演示过程会改存档（答了的岔路不会回来），所以每次都从 `polis-pitch-master.db` 重新复制。
存档放了超过约 9 天（比它的快进量还久）`--rewind` 会拒绝，重新生成即可。

默认路径 `./polis-test.db` 就是 `npm run dev:test` 读的那个；用别的路径：
`POLIS_TEST_MODE=1 POLIS_DB_PATH=<path> npx next dev`。

首次用某个浏览器档案时会出现 4 步新手气泡（气泡里有「跳过」）；点标题上的按钮同时解锁音频。建议用一个干净的窗口，
窗口 1440 × 900 左右。浏览器时区不影响世界（时区已写进存档）。

## 路线（总长约 6–7 分钟，每步标了大约用时）

**0. 标题（0:30）** 背景是正在运转的小镇。按钮写「继续 · 阿守 · 第 10 天」。
> 「这不是新开的一局，它已经在这个小镇里生活了九天。」点「继续」。

**1. 进城，认识它（0:45）**
金色光圈是它。左上卡片和顶部「当前行动」写着它在做什么、**为什么**（例如「你说过『…』」「今天我自己拿了主意」）；
称号和外号（守约的 / 敢闯的…）都来自真实记录，不是随机贴的。
> 「你没有身体，不能操控它。它按你教过它的东西自己过日子。」
如果进来先弹出「质问」窗口（它对自己的一条原则有点动摇了）：这是第四个动词，选「重申：它没错」或「修订这条原则」都行，当场讲一句即可；
不一定每个存档都有。

**2. 回应岔路：它可能不同意（1:30）**
点底部「岔路」（或按 1 / 2 / 3）。窗口里是它第一人称的难题、一栏「可核查的记录」（全是数据库里的事实）、
有时还有一行「两条原则在打架」。**答哪个选项**：看你小抄的 `IF THE PRESENTER ANSWERS` 段——挑那个标着 `refuse` 的。
选后会弹「它的回应」：标签「拒绝」，一句「这次我想按自己的判断来……你说过『…』——所以我打算『…』」，
下面「依据」几条都是真实的行（有时就包括那次「被迫」）。
> 「它没有顺着你。它引用的是你自己说过的话，依据是账上的事实。」

如果答了之后它说的是「好，我照你说的做」（execute）或调整（adjust），也别慌：讲「它同意，但会记着这是你的意思」，
然后用第 3 步的已有记录接着讲拒绝。

**3. 强制执行与它的代价（1:00）**
拒绝窗口里有两个按钮：「尊重它的判断」（零成本，它按自己的来）和红色的「强制执行（30 Scrip · 信任 -10）」。
- 想现场演：点强制执行。讲三件事：花 30 Scrip（销毁，永久消失，账本里能看到）、信任 -10、**它不会忘**——
  它会记下一条「被迫」的烙印，之后的判断里会引用。（前提：Scrip ≥ 30，小抄里 PENDING 段末行会写。）
- 不想花：存档里本来就有一次早先的强制执行（小抄 `forced` 段，在第 5 天附近）。不点它，直接去第 4 步看它的后果：
  那条被迫烙印，以及后来的拒绝里「你曾在『…』时强迫我」这句依据。

**4. 烙印抽屉（0:45）**
按 R。顶部「记忆 5/5」是槽位：新烙印进来，最久没用的会慢慢沉睡（可唤醒）；「扩展记忆 +1 格（200 Scrip）」。
每条烙印写着类型（信任 / 风险 / 原则）、来源（规则凝练 / 来自你的留言 / 被迫）、诞生场景一句话、被引用次数。
> 「每个选择都是一条会被它引用的原则；玩家塑造的是它的记忆，不是它的手。」
右上的「默契 x/y」是玩家猜它会怎么选的命中率；如果存档里有待猜的默契（小抄 `默契 guess` 段），屏幕上没有窗口时会自动出现一张默契卡片
（收起后变成一个小标签，点开即可）：先猜一次，稍后（傍晚前）它自己拿主意并公布对错。

**5. 记忆 tab：谁的主意（0:45）**
抽屉顶部切到「记忆」，用标签过滤：「你的话」是你说的、「它认同」「它没认同」是它对你建议的态度、「被迫」是强制执行留下的、
「它做了」「后来」是它自己的行动和结果、「别人」是听来的。小抄 `memory tags` 段列了每类的一句例子。
> 「同一件事，谁的主意写得清清楚楚。」

**6. 关系 tab：传闻带出处（0:45）**
切到「关系」。每位居民一张卡：熟悉度、合作次数、谁记着谁什么事。**传闻写明来源**——「Kade 听 Sol 说：…」「我听 Tao 说：…」。
小抄 `hearsay` 段的 `on screen` 行就是此刻能在这个 tab 看到的那几条；`chains` 段把同一件事的前因后果串成「过错 → 谁传的 → 后来的拒绝 / 借款 → 置业 → 还或赖」，
每一环是 `表#id`，现场被质疑时可以说「每一行都能在存档里查到」（`node scripts/causal-chains.mjs ./polis-test.db`）。
> 「没有一句传闻是编的：谁说的、对谁说的，都是一行记录。」

**7. 公告栏（B）→ 账本（L）（0:45）**
公告栏：本周履约榜（你的 Agent 排第几、称号）和「本周的事」，里面能看到它的拒绝和你的强制执行原话。
账本：切到「昨天」，进账、赔损、**销毁**（任务 5% 手续费，加上槽位和指令券的花费，是从城邦里永久消失的）。
> 「数字只在账本里；明信片不写收益率，故事和账分屏。」

**8. 明信片与档案卷（1:00）**
按 P。「第 9 天」那张是未读的，红点标着：当晚它写给你的话，只用当天的真事，引用你的原则（高亮），底部写着「由规则整理」。
再切到「档案」tab：第 1 卷（入城第七日，Iris 整理）——完成多少单、新的烙印、**高光**（常常就是它那次拒绝的原话）。
**「下周看点」只出现在第 2 卷起**（入城第 14 天夜里），第 1 卷里没有它。想演这一段（多出约 1 分钟）：
测试快进面板连点「+24 小时」4 次，再点「到今晚 23:00」，必要时「+1 小时」，打开 P → 「档案」→ 第 2 卷。
第 2 卷还会引用你给第 1 卷写的三个词（「上一卷，你用三个词形容它：…」）。
下周看点读的是仍然开着的线（还没到期的借款、没松口的旧怨、差一点的置业），例如「X 还记着它（…），会松口吗？」。
> 快进期间没回应的岔路 24 小时后由它按原则自己决定——这本身也是一个讲点，但会改变存档里的待办，所以放在最后。

## 如果现场不是预想的样子

| 情况 | 办法 |
|---|---|
| 小抄 PENDING 写着 `NO`（没找到有待办的白天） | 重新生成：`npm run scenario -- pitch --db ./polis-pitch-master.db --force --tries 6 --extra-hours 48`；或走下面「没有待办」 |
| 打开后没有岔路、也没有默契 | 不要等。直接从第 4 步开始：拒绝和强制执行是已经发生的事，在抽屉、记忆 tab、公告栏、「看全部」动态里都能指给人看（把第 2–3 步改成讲述） |
| 想再来一个岔路 | 测试快进面板点「+1 小时」；岔路有频率上限（同时 ≤3、间隔 ≥4 小时、每天 ≤3、同模板 48 小时一次），可能要几小时；快进改变存档，别在讲到一半时做 |
| 答了之后它没拒绝 | 它同意也是看点（「我会记着这是你的意思」）；转第 4 步，用存档里已有的拒绝记录讲立场 |
| 强制执行按钮是灰的 | Scrip 不足 30 或这条不是拒绝；改选「尊重它的判断」 |
| 传闻 tab 里没有「听 X 说」 | 说明传闻已经过期（一周后淡出）或被「亲眼所见」覆盖；改用 `WHAT TO SHOW` 的 `hearsay` 行和动态里「X 跟 Y 聊起了 Z」的条目 |
| 时钟走偏了（夜里了） | 停 dev server，重新「复制原件 → `--rewind` → `dev:test`」 |
| 页面出现意料外的弹窗 | Esc 关最上面一层；没处理完的判定会先弹出，其次是你自己打开的窗口，最后才是质问；逐个处理即可 |

## 附：脚本做了什么 / 没做什么

- 全程只用游戏的 HTTP API（建玩家、答岔路、判定的接受 / 强制 / 推翻、猜默契、留言、读明信片、三词问卷）和 `/api/test/advance`；
  没有任何直接写库的叙事。唯一直接动库的是 `--rewind`，它只改 `world_state.time_offset_ms`（时钟），不碰任何剧情行。
- 守护灵策略 = `scripts/sim-playthrough.mjs` 的 bold：岔路选第一项，第一次遇到拒绝就强制执行，之后接受，其他判定推翻，默契猜第一项，
  前两晚留言「做人要说话算话」，第一卷问卷填「敢闯、讲义气、有主见」。
- 停下来的条件：白天 09–16 点；有一个剩余 ≥ 3 小时的岔路，或一个剩余 ≥ 1.5 小时的待猜默契；至少一张未读明信片。
  评分要的是：有拒绝、有强制执行的烙印、有居民难处、有传闻（最好此刻还在关系 tab 上）、有第 1 卷；有借款置业更好。
  不满足就逐小时往后找（`--extra-hours`，默认 30），再不行整局重来（`--tries`，默认 4），留最好的一份。
- 「IF THE PRESENTER ANSWERS」那一段，是在存档的**副本**上、用 `POST /api/decisions/:id/choose` 真的答一遍得到的；
  离线规则引擎对同一个状态是确定的，所以真存档上会得到同样的回答。（只试剩余时间最长的那个岔路——它最不会在你讲到之前自己过期；先答了别的岔路，它的结果可能会变。）
